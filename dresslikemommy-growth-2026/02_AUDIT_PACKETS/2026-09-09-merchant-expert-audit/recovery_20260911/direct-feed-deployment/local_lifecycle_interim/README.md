# Local US feed lifecycle interim

This is a bounded successor to the already used local US R2 uploader. It is not a scheduler, Worker deployment, new source or international release. Shopify credentials stay in the existing private Mac file and go only to the expected Shopify Admin endpoint through the frozen reader. Cloudflare receives the public US feed/manifest through the existing authorized local Cloudflare path. No credential is added to a Worker.

Merchant task `01a08706-c63a-7e01-ba48-7777bcb1788a` remains the sole writer for `merchant/us-en/current.json`. Parent `01a08223-036e-7fa3-8961-ecd297163fb5` owns cadence/dispatch through its existing heartbeat. All previous price-only upload scripts, rejected cloud jobs, manual account changes and other writers must stay idle during a run. The local process lock excludes this uploader's concurrent processes. The REST pointer comparison detects drift; **it is not server-side CAS**. If any independent remote writer is introduced, stop until real cross-writer exclusion is established.

The exact target is Merchant513542500/source10727274744, US/en/USD, free listings. Preserve its existing URL and daily12AM NewYork fetch. AU/CA/GB and Google-discovered sources are outside this executable's scope.

Use the bundled Python executable with this directory's `lifecycle.py`. Each run is a new child of `runs/`, with a name such as `20260911T213300Z-us-refresh`. Never recycle a failed run or its approval. Commands are sequential:

1. `prepare --run ABSOLUTE_RUN_PATH` captures current remote pointer, original full TSV and both Worker metadata records. It does not publish.
2. `build --run ABSOLUTE_RUN_PATH` runs the unchanged 28-file frozen builder with explicit US config, `--live`, and the captured previous manifest. It strips inherited Shopify credential overrides, uses the existing private credential convention, and records the actual command/start/end/result. Full live source pagination must finish. It then applies the copied exact parent-hold specification through the pure byte-preserving filter. The original four files remain under `unfiltered/`; the complete source snapshot/counts/timestamps are preserved. `contain --run ABSOLUTE_RUN_PATH` is the local-only one-time equivalent for an already completed fresh scan when new evidence has required containment. This reuses real source evidence without restamping it; the final reviewer must reconcile current source drift and freshness. No failed-read snapshot fallback is accepted.
3. The independent reviewer reads the candidate packet, before feed, complete new snapshot, diagnostics and changed rows. Check every price/eligible row against source, missing/removed IDs against the complete source, source freshness, current single-writer claim, actual buyer qualification for additions, and the unchanged config/Worker contract. The reviewer also checks the exact uploader code and tests. No new owner question is required for already-authorized routine lifecycle work; unresolved commercial/source/access decisions remain their actual gates.
4. `promote --run ABSOLUTE_RUN_PATH --review ABSOLUTE_REVIEW_PATH --review-sha256 EXACT_REVIEW_SHA` is the only publication command. The independently written JSON must say `decision: APPROVE_EXACT_US_FEED_POINTER`, `independent: true`, identify the independent reviewer, copy all 16 binding fields required by `validate_review`, and set `source_eligibility_and_all_prices_verified`, `source_eligibility_holds_verified` and `single_writer_claim_verified` true. Added IDs require the exact `buyer_qualified_added_ids` set; mass removal requires explicit reviewed evidence. Prices above USD1000 are held for a separate exact source decision, not automatically repaired.
5. `readback --run ABSOLUTE_RUN_PATH` confirms full remote pointer/object, unchanged Worker metadata and public URL bytes/context/source timestamp. A fresh public cache can lag; record that actual limitation and use a later bounded readback, not another publication.

Promotion locks locally, rereads current remote state, verifies an existing immutable object or uploads one exact SHA-keyed object, verifies full bytes and ETag, rechecks Worker metadata and pointer immediately before one commit, then reads the result. An uncertain pointer response triggers reads only. Repeating an already committed exact run performs reads; an ambiguous uncommitted attempt stops. A partial uploaded immutable object is never promoted. No failure path publishes empty/partial data or automatically restores old broken prices.

The known Admin API transport ETag `W/"<md5>-gzip"` is accepted only when its embedded MD5 equals the reviewed manifest and the complete decoded response also passes both SHA256 and MD5. A normal quoted raw MD5 is also accepted; missing, malformed, wrong-hash or other transformed ETags fail. This does not bypass the unchanged public Worker's separate raw R2 binding ETag check. All reviewed artifacts and source age are rechecked again immediately before the pointer PUT so a slow upload cannot commit an expired candidate.

Unchanged TSV bytes still require a complete fresh Shopify scan and an independently reviewed genuine `sourceCompletedAt` renewal. Old timestamps must never be restamped. Candidate scans expire after120minutes for promotion; the existing public host's48hour source-age safeguard is unchanged. The Mac must be powered/awake, online and able to execute the existing task; this interim does not claim always-on operation. Google receiving, approval, impressions, sales and removal lag remain separate from local/hosted completion.

The source-hold filter has no external access and can also derive an independently reviewed AU file from a fresh complete AU scan. It never labels held products out of stock or changes Shopify status. Any AU native upload/host route requires separate exact receiving and market qualification; this US publisher cannot publish AU. Hold-file changes require a newly bound review, and removals of holds require the stated source/buyer repair evidence.

Every held parent must occur in the complete source identity list. A known parent with no available rows is reported separately; an unknown parent stops the run. Both containment and replay protect the current pilot variant and the five corrected-price variants. The current active hold file and exact source qualification artifact are bound at review and checked again immediately before pointer commit. A change during upload prevents that commit. The preserved local revision history records earlier failed candidates; it does not authorize them.

Offline validation: `python3 -m unittest -v test_lifecycle.py test_cohort_filter.py`; real original4,923-row manifest validation and all28 frozen-file hashes also pass. The new code is independently reviewed before any `promote`. No production lifecycle run or parent cadence integration is implied by the existence of these files.
