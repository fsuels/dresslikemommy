## Recommended repair path

Keep the existing account/tag identity and ask Microsoft's Channel maintainer to resolve the observed consent mismatch and confirm purchase identifiers. The [Microsoft Channel listing](https://apps.shopify.com/microsoft-advertising) identifies Microsoft as developer/support owner and advertises checkout and conversion tracking; it does not establish native CAPI, enhanced-conversion or refund synchronization.

Shopify says app-defined pixel privacy permissions cannot be merchant-edited. Server pixels are available to certain app owners, not automatically every app. Separately, merchants can choose Optimized/Always on data access and inspect an activity log beginning June 3, 2026. Review that log once if unexplained missing events persist; changing data access is not a consent repair. Also check customer-account domain alignment for order-status consent. [Shopify app pixels](https://help.shopify.com/en/manual/promoting-marketing/pixels/app-pixels)

A supported alternative exists: Microsoft's [Shopify UET example, dated May 30, 2026](https://raw.githubusercontent.com/MicrosoftDocs/Advertising/main/advertising/msa-help/hlp_BA_PROC_UET_WebPlatform_Shopify.md), documents a Customer Events custom pixel. It maps `checkout_completed` to `purchase` and uses checkout total amount/currency. However, the inspected sample hardcodes granted consent, omits `event_id`/`transaction_id`, and lacks a revocation listener. **Do not paste it as an additional sender.** If publisher repair fails, prepare an independently reviewed replacement with explicit consent, stable identifiers, one purchase sender, compatibility tests and rollback. This is a replacement design, not a bridge into Microsoft's private app runtime.

App pixels run in strict workers; custom pixels run in lax iframes, without top-frame access. Use Shopify event context for actual URLs. A theme queue cannot be assumed to control either sandbox. Shopify replays registered events after permitted consent in applicable regions, so test replay ordering. [Sandbox documentation](https://shopify.dev/docs/apps/build/marketing/pixels)

The non-Plus Thank you/Order status upgrade deadline was August 26, 2026. Rebuilding checkout tracking with old Additional scripts is inappropriate. This deadline does not itself prove this store's migration state. [Current upgrade guide](https://help.shopify.com/en/manual/checkout-settings/customize-checkout-configurations/upgrade-thank-you-order-status/upgrade-guide)

Copilot direct checkout is a separate measurement surface: Shopify says its standard/custom client pixels and Google Analytics do not fire there; only server-to-server started/completed pixels fire. Keep these orders in a separate reconciliation cohort and establish the supported server receiver before promising UET coverage. Redirected online-store checkout follows a different path. [Copilot checkout limitations](https://help.shopify.com/en/manual/online-sales-channels/agentic-storefronts/microsoft)

## Purchase and consent contract

Shopify's `checkout_completed` normally occurs once per checkout, potentially on the first upsell page; if its trigger page fails to load, no event occurs. Available fields include event ID/time, checkout order, currency, line items and money values. Keep event ID, order identifier and customer/client identifier conceptually separate. An event subscription's success does not prove downstream delivery. [Event schema](https://shopify.dev/docs/api/web-pixels-api/standard-events/checkout_completed)

For UET revenue, validate `revenue_value` and uppercase `currency`, using a decimal point. `event_value` is not a substitute for revenue. Maintain the existing variable-value purchase goal while verifying its exact payload. [Variable revenue](https://help.ads.microsoft.com/apex/index/3/en/56687)

Choose and document the value basis: app-reported checkout total versus retained merchandise revenue used for economics. Shopify changed checkout subtotal to include product and order discounts in April 2025; do not subtract the same discount twice. Reconcile tax, duties, shipping and refunds separately. Preserve original currency and the reporting FX basis. [Subtotal change](https://shopify.dev/changelog/web-pixels-api-eventdatacheckoutsubtotalpriceamount-value-change-on-the-new-thank-you-page-and-checkout-events)

The maintainer should consume initial `init.customerPrivacy` and later `visitorConsentCollected` states, preserving analytics/marketing/sale-of-data distinctions. Shopify loads app pixels only when all declared permissions are available. Do not treat email-marketing opt-in as tracking consent. [Pixel Privacy](https://shopify.dev/docs/api/web-pixels-api/pixel-privacy)

Microsoft supports Basic consent mode, which blocks UET until permission, and Advanced mode, which starts with denied consent and supports aggregate modeling. Regional enforcement covers EEA/UK/Switzerland; inspect each event's consent signal and actual ordering. Missing `asc` is a diagnostic, not evidence of permission. A no-regional-sample Healthy tooltip cannot certify regional purchases. Advanced mode is not permission to override Shopify's gating. [Microsoft consent documentation, June 18, 2026](https://raw.githubusercontent.com/MicrosoftDocs/Advertising/main/advertising/msa-help/hlp_BA_CONC_UET_Consent.md)

TCF is a documented alternative when the CMP implements it correctly. Microsoft's document lists vendors 1126/32 and purposes affecting cookies, measurement and personalization; record the actual string interpretation and CMP response, rather than manufacturing consent. The page still calls its integration TCF v2.0; confirm current CMP compatibility with its maintainer. [Microsoft TCF](https://raw.githubusercontent.com/MicrosoftDocs/Advertising/main/advertising/msa-help/hlp_BA_CONC_UET_TCF.md)

## Server-side, enhanced conversions and adjustments

Microsoft CAPI exists. Its August 4, 2026 guide supports direct/partner/server-tag-manager integrations, `value`/`currency`/`transactionId`, and browser+CAPI dedup through matching tag/name plus UET `event_id` ↔ CAPI `eventId`. Events must be within seven days. Explicit `adStorageConsent=D` excludes advertising use; omission defaults to granted. HTTP200 may include removed-field warnings. The items array is not used by standard conversion goals. None of this proves Channel implementation. Require publisher confirmation and stable IDs before adding a second delivery path. [CAPI guide](https://learn.microsoft.com/en-us/advertising/guides/uet-conversion-api-integration?view=bingads-13)

Enhanced conversions separately require an enabled goal and appropriately handled first-party email/phone signals. They supplement matching; they do not prove purchase value or incrementality. [Microsoft enhanced conversions](https://raw.githubusercontent.com/MicrosoftDocs/Advertising/main/advertising/msa-help/hlp_BA_CONC_UET_EnhancedConversions.md) Shopify app pixels require approved protected scopes for these fields, enforced December 10, 2025; unavailable fields can be null. Do not enable or upload customer data during this planning work. [Shopify scope change](https://shopify.dev/changelog/protected-customer-data-scopes-required)

Microsoft documents online restate/retract as a pilot requiring the original transaction identifier. Restate changes value; retract removes the conversion. The online API is separate from the CAPI event endpoint. Its schema uses goal name, TransactionId, UTC adjustment time and adjusted value/currency. [Conversion behavior/pilot](https://help.ads.microsoft.com/apex/index/3/en/56710), [online object](https://learn.microsoft.com/en-us/advertising/campaign-management-service/onlineconversionadjustment?view=bingads-13), [operation](https://learn.microsoft.com/en-us/advertising/campaign-management-service/applyonlineconversionadjustments?view=bingads-13)

The online documentation contains inconsistent offline/click-ID wording; confirm account eligibility, original identifier availability and permissible adjustment age before implementation. No automatic Shopify refund feed is established. Offline adjustments apply to previously imported offline conversions, keyed to the original conversion; the documented original-conversion age is 90 days, also constrained by the goal window. Do not apply that limit to online adjustments by analogy. [Offline adjustment schema](https://learn.microsoft.com/en-us/advertising/campaign-management-service/offlineconversionadjustment?view=bingads-13)

## End-to-end QA protocol — proposed, not run

Run only through owner-authorized test facilities or genuine orders; isolate any test data from production bidding. Do not click live ads or manufacture purchases to obtain attribution proof.

| Stage | Required evidence and pass condition |
| --- | --- |
| Identity | Snapshot account/customer/tag, installed senders, app version, purchase goal/name/window, primary/secondary roles. One primary purchase goal; no overlapping legacy URL purchase counting. |
| Consent matrix | US, Germany/EEA, UK and Switzerland where supported; desktop Edge/Chrome and mobile Safari/Chrome. Test initial no-choice, denied, granted, granted→revoked, reload and cross-page navigation. Observe banner choices without consent setters; align Shopify state, sandbox callback timing and UET signal. Basic blocked delivery is expected while denied. |
| Storefront path | Localized landing→product→cart→standard checkout; repeat with enabled accelerated methods such as Shop Pay/PayPal. Verify market/language/currency, redirects, customer-account domain and consent continuity. Test only enabled methods, not assumed capabilities. |
| Purchase payload | Bind one authorized order to sender timestamp, event/transaction identifiers, receiving tag, value/currency and distinct item quantities/prices. Test USD plus each funded non-USD market, discounts, shipping/tax, multi-item orders and post-purchase offers. Missing fields remain failed/unknown, not replaced by defaults silently. |
| Dedup | Confirmation reload, back/forward, reopened status page and retries must not create another purchase. A second genuine order by the same buyer must count separately. Inspect every sender/goal; shared CAPI IDs do not cure duplicate goals. |
| Transport/receiver | Preserve sanitized request/response and native receiver evidence. Match the same order where technically exposed. Parameter names or a daily count alone fail exact-match acceptance. Record warning/lag conditions and receiver limitations. |
| Attribution | On subsequent legitimate ad traffic, verify MSCLKID/UTMs survive routing and match the intended campaign; align timezone, conversion window/model and view-through reporting. A direct order can reach UET without an attributed ad conversion. |
| After sale | Reconcile cancellations, partial/full returns and updated totals to Shopify. Where approved/eligible, read back adjustment acceptance and revised reports. Maintain retained-revenue economics even if platform adjustments are unavailable. |

Account UTM auto-tagging can duplicate manually appended UTMs; use the URL test and actual resolved URL. UTMs describe traffic source; MSCLKID enables Microsoft click linkage. Neither a placeholder click ID nor a URL test is a genuine ad click. [UTM documentation](https://help.ads.microsoft.com/apex/index/3/en/56762), [UET identifier reference](https://help.ads.microsoft.com/apex/index/3/en/53056/)

Report five separate results: **receipt; payload correctness; attributed purchases; incremental lift; contribution profit**. For the last, join distinct Shopify orders to retained merchandise revenue, actual supplier/shipping/payment/return costs and Microsoft spend, using comparable periods and return maturity. Attribution alone cannot establish incrementality; one purchase cannot establish a stable conversion rate. Preserve the USD0.15 CPC constraint and current launch/cash-loss authority.
