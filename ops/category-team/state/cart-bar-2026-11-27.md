# Mobile cart: sticky Check out bar on first paint + wrapped option names (2026-11-27)

Commit `0b7841e` on `main` (Shopify follow-up `ecd1242` has an empty diff; main = this change). Live theme synced: 4 applied, re-check 0 differ.

## Causes
1. Sticky bar late: the bar was `visibility:hidden; translateY(100%)` until `assets/cart-sticky-checkout.js` added `.is-ready`. That script is `defer`, placed mid-body, so it runs only after the whole HTML is parsed and after ~50 earlier deferred/sync scripts. It then waited for the first IntersectionObserver callback to add `.is-visible`, then a 0.2 s slide-in. Body bottom padding was also added only after `.is-ready` (late reflow). Theme cause, not an app.
2. Spanish colour cut off: a global `table { display:block; overflow-x:auto; white-space:nowrap }` rule in `assets/theme-inline-head-static-03.css` (meant for size charts) also hits the cart `table.cart-items`. The details cell would not wrap, the row became 418 px in a 345 px table and was clipped/scrolled (title and "Color: Panda en el jardín de bambú – color crema").

## Diff summary
- `assets/component-cart.css`: on <=749 px the bar is laid out visible by default; new `.is-hidden` state hides it (same slide transition); `#main-cart-footer.is-empty` hides it; body bottom padding and Undo-toast lift no longer depend on `.is-ready` (applied from first paint).
- `assets/cart-sticky-checkout.js`: only toggles `.is-hidden` (main button in view or cart empty); no `.is-ready`/`.is-visible`.
- `sections/main-cart-footer.liquid`: comment updated; removed initial `tabindex="-1"` (bar is now visible on load). Same label, total and `form="cart" name="checkout"` target.
- `assets/component-cart-items.css`: on <=749 px `.cart-items .cart-item__details { white-space: normal }` and `overflow-wrap:anywhere` on option values. All languages. Desktop untouched (media query).

# Undo notice when the LAST item is removed on /cart (2026-11-27, unit 3)

Commit `72c00d7` (assets/cart.js only); theme synced (1 applied, re-check 0 differ). THEME_LOCK held 07:49Z to 07:53:30Z. Shopify export `fb0c596` and a fetch after 3 minutes still match my cart.js.

Cause (found by Quality V106, existed before c4f346e): after the cart emptied, cart.js called `trapFocus(cartDrawerWrapper.querySelector('.drawer__inner-empty'), …)`. On /cart the drawer has no such element, so trapFocus threw. That skipped the Undo toast and the catch wrote the cart error.
Fix: trapFocus only runs when that drawer element exists; otherwise the flow continues to the toast. No text or style changes. The drawer still traps focus on its empty state when it has one. The 2-item branches are unchanged.

Verification (built-in browser, 375 px, 7 store loads 10 s or more apart, plus 1 cart.js read):
- `/` (EN): 1 item -> trash: "Item removed Undo" shown, no cart error, bar hidden (empty cart). Undo -> item back (Child 2 Years, Bamboo Garden Panda Cream, qty 1), sticky bar visible again at 743 px.
- `/es`: 2 items -> remove one: "Artículo eliminado Deshacer", 1 line left, bar shows €38,95. Remove last: toast shown and visible, no error, footer empty.
- Console: only the known 401s. No horizontal overflow (375). Cart ends empty (item_count 0).
- Not exercised: the cart drawer itself (it opens from product pages; the load budget was used). Its code path is only changed when `.drawer__inner-empty` is missing.
